# GOSTC 平台增强 · 开发路线图

> 版本：v1.6 ｜ 状态：全部完成（P1–P6 后端 + P2 前端 + 全量构建/测试/CI/文档）｜ 配套：[产品文档](产品文档.md)、[PRD](PRD.md)

## 1. 总体策略

- **文档先行**：Phase 0 产出三份文档并评审，确认后再写代码。
- **增量交付**：6 个实现阶段，每阶段独立可发布、可回滚、有验收门禁。
- **依赖优先**：先做底座（安全/缓存），再做依赖它们的能力（告警/证书/可观测）。
- **向后兼容**：DB 只增不删；旧客户端/旧哈希平滑兼容；feature flag 控制新功能。

## 3. 依赖图

```
P0 文档 ──► P1 安全+缓存 ──┬─► P2 可观测+告警 ──┬─► P4 frp表单化
                          │                    └─► P5 高可用
                          └─► P3 证书+网关
P1–P5 ──────────────────────────────────────────► P6 商业化+生态
```

关键依赖说明：
- **M1 告警**依赖 M3 Redis（节流/共享态）与 M2 审计；**M7 实时指标**依赖 Redis 时序窗口。
- **M4 证书**依赖 M2 凭据加密（DNS AK 加密存储）。
- **M5 健康检查**复用 M1 探测框架；**M8 故障转移**依赖 M1 节点健康 + dbresolver。
- **M9 支付**依赖 M2 安全（回调验签/凭据）；**M10 API Token**依赖 M2 加密。

## 4. 各阶段开发步骤与验收门禁

### P0 文档（先行）
1. 写 `docs/product/{产品文档,PRD,开发路线图}.md`，挂载 `_sidebar.md`。
2. **门禁**：用户评审 PRD 通过 → 进入 P1。

### P1 安全 + 缓存底座
1. `server/pkg/crypto` AES-GCM 工具 + 主密钥配置；凭据加密迁移（幂等）。
2. bcrypt 登录透明升级（`service/auth`）。
3. TOTP 2FA（`pquerna/otp`）绑定/校验/恢复码。
4. 审计中间件 + `SystemAuditLog`；登录限流锁定（`x/time`）。
5. 准入黑名单字段。
6. go-redis 实现 `memory.Interface`；`bootstrap/memory.go` 按配置选择 + 降级。
7. 新表/列注册 `persistence.go`；补单测。
- **门禁**：旧用户无感登录、库内无明文密钥、2FA 生效、双实例缓存共享、现有隧道无回归。

### P2 可观测 + 告警
1. 隧道健康三态字段 + 定时探测任务（cron）。
2. frps plugin / 节点查询确认注册态；后端主动探测。
3. `SystemAlertRule/SystemAlertLog` + 邮件/Webhook 渠道 + 静默。
4. 实时指标采集（plugin+心跳）+ Redis 窗口 + 聚合落库。
5. 前端健康徽标/总览/告警管理/echarts 仪表盘。
- **门禁**：后端宕机 ≤1 周期变红并告警；实时指标可见；无误报风暴。

### P3 证书 + 网关
1. lego 集成 + DNS provider（DNSPod/Cloudflare）；`SystemCert` + 续期 cron。
2. 证书下发到 proxy/节点；上传/到期/手动签发 UI。
3. proxy 死配置清理 + 通配符 bug 合入上游 + IP 路由 + HTTP/3 开关。
- **门禁**：面板一键签出受信任证书并自动续期；通配符非标端口回归通过。

### P4 frp 表单化
1. host/forward 模型增高级字段 + engine 映射。
2. 负载均衡/健康检查/HTTP 路由/tcpmux/范围端口/带宽限制表单。
3. 旧客户端版本兼容处理。
- **门禁**：多后端负载均衡+健康检查切换生效；HTTP 路由/范围端口生效。

### P5 高可用
1. 节点分组/优先级/权重；隧道备节点 + failover。
2. 客户端多节点注册；离线自动切换重推。
3. dbresolver 读写分离配置。
- **门禁**：主节点宕机自动切备节点恢复；读写分离生效。

### P6 商业化 + 生态（可拆子迭代）
1. M9 支付网关框架 + 沙箱 + 订单账单 + 回调验签（商户资质确认后接真实渠道）。
2. M10 OpenAPI + API Token + SDK + 批量 + 模板。
3. M11 Webhook + 客户端自动更新 + i18n。
4. M12 P2P NAT 预检 + 中继计费。
- **门禁**：沙箱支付全链路幂等；OpenAPI/SDK 可用；自更新校验回滚；i18n 切换。

## 5. 横切工程约定

- **Schema**：gorm AutoMigrate 只增列/表；新 model 注册 `bootstrap/persistence.go`；提供幂等迁移。
- **配置**：`server/configs.Config` 增 `Cache/Encrypt/ACME/Alert/Pay/DBResolver` 段；环境变量覆盖；feature flag。
- **测试**：每阶段表驱动单测；`.cirrus.yml` 增 `go test ./...` + `web build`；关键路径（bcrypt/探测/ACME/支付回调/Redis）必测。
- **构建/部署**：server/client/proxy 交叉编译 + goreleaser；proxy 沿用「替换二进制重建镜像」；web vite build；部署到用户服务器。
- **回滚**：阶段独立发布；DB 只增不删；feature flag 关闭即回旧行为。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 凭据加密迁移丢数据 | 幂等迁移+版本前缀+迁移前备份+解密失败明确报错不静默 |
| bcrypt 升级锁死旧用户 | 升级失败保留旧哈希仍可登录 |
| Redis 引入不稳定 | 降级 local + 告警，灰度切换 |
| 健康探测误报/压后端 | 区分节点不可达 vs 后端故障；频率可配/可关 |
| ACME CA 限流/DNS 失败 | 退避重试、保留旧证书、前置校验 |
| 故障转移抖动 | 冷却期防反复切换 |
| 支付回调安全 | 验签+幂等+主动查单补偿+金额校验 |
| 范围过大进度失控 | 阶段门禁+feature flag+P6 拆子迭代 |
