# 故障转移场景与「入口跟随」缺口分析

> 归档（CCG 六要素）· 2026-11-28
> 说明：本会话未配置 cg/记忆 MCP（discover_project_mcp 为空），无法产出记忆节点 id；
> 以本仓库文档作为持久归档载体，写回后可用 read/grep 检索复核。

## 功能名
节点组故障转移（node-group failover）+ 入口跟随（待增强）。

## 生效条件
- `health.enable=true`（巡检/转移总开关），巡检周期 `health.interval-sec`（默认 30s）。
- 隧道 `FailoverEnable=1`。
- 主节点心跳离线（`GetNodeOnline==false`），且不在 5min 切换冷却期。
- 有可用备节点：显式 `BackupNodeCode` 在线，或主节点 `GroupCode` 同组内有在线节点（按组策略 priority/weight/random）。

## 子功能
1. 五类隧道迁移：host(域名解析)/forward(端口转发)/proxy(私有代理)/tunnel(私有隧道)/p2p。
2. 备节点选择：显式备节点优先 → 同组策略调度（node_select）。
3. 切换动作：改 `NodeCode` + 落库 + 重推客户端配置 + `node_failover` 告警；无备则 `tunnel_down` 告警。
4. 冷却防抖 5min；注册态由探测 ground truth 重建（重启即恢复）。

## 执行
`server/task/failover.go failoverScan()` → `gatherFailoverItems`(FailoverEnable==1 五类) →
`pickBackup` → `switchTunnelNode`(engine.Client{Host/Forward/Proxy/Tunnel/P2P}Config) →
`SetFailoverCooldown` + `alert.Dispatch`。节点重连经 `global.HealthProbeTrigger` 触发即时探测。

## 验证方式
- 单测 `server/task/failover_test.go`：TestPickBackup / GroupAllOffline / Cooldown / E2E / DecideHealth。
- 生产实测：面板重启 +16s 健康总览 healthy8/abnormal2（注册态立即准确）。

## 不适用条件 / 缺口（入口跟随）
故障转移只迁「隧道注册」，**不改外部入口**，故：
- host 前缀域名：URL 变为 `前缀.备节点Domain`（新域名解析到新 IP）→ 新地址可用、旧地址失效。
- host 自定义域名：URL 不变但 DNS A 仍指旧节点 IP → 断，需改 DNS（未实现自动 DNS 故障转移）。
- forward 端口转发：公网入口 = 节点IP:远程端口，转移后 IP 与端口都可能变 → 调用方硬编码地址失效；无 DNS 可改（DNS 不携带端口）。
- proxy/tunnel/p2p：访客/代理入口 likewise 依赖节点地址，存在同样入口跟随问题。
- 节点在线但单隧道后端坏：不触发转移（触发是节点级）。
- 无自动回切（failback）。

## 端口转发专项
- 备节点端口约束：`forward.Port` 须在备节点 `ForwardPorts` 范围内且空闲，否则注册失败。
- TCP 长连接转移后断开，需重连新入口。
- 无缝方案：前置 TCP LB/HAProxy/nginx stream/VIP/云 LB；或 SRV 记录（需客户端支持）；或固定端口 + DNS A 跟随。

## 建议增强（待立项）
统一「入口跟随」层：host 自定义域名 → 复用 ACME DNS provider 自动改 A 记录；
forward → 尽量同端口 + failover webhook 携带新入口供调用方自动切换；或前置稳定 LB。
