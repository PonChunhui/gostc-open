# 入口跟随（Entry Follow）产品文档

> P7 · 故障转移增强 · 2026-11-28

## 1. 背景与问题
现有节点组故障转移（P5/M8）只迁移「隧道注册」：主节点离线时把隧道切到备节点并重推客户端配置。
但**外部访问入口不跟随**，导致转移后访问中断：

- host 自定义域名：DNS A 仍指旧节点 IP → 断。
- host 前缀域名：URL 变成 `前缀.备节点Domain`，旧地址失效。
- forward/proxy：公网入口 `节点IP:端口`，IP 与端口都可能变 → 调用方硬编码地址失效。
- tunnel/p2p：访客 `serverAddr` 指向旧节点 → 信令/中继断。

## 2. 产品定位
为故障转移补上「入口跟随」层：**隧道搬到哪，外部入口就跟随到哪**，且**公网端口保持不变**（只允许 IP/域名变化），覆盖全部五类隧道。

## 3. 核心原则
1. **同端口硬约束**：备节点无法提供与主节点相同的公网端口时，放弃本次转移并告警，绝不静默改端口。
2. **域名跟随**：host 自定义域名自动更新 DNS A 到备节点 IP。
3. **入口可感知**：所有转移产生「旧入口→新入口」结构化 webhook + 历史记录，供调用方/运维感知。
4. **可选回切**：主节点恢复后自动回切（failback），同样遵守同端口约束。

## 4. 各类隧道入口定义
| 类型 | 公网入口 | 公网端口（不变） | 备节点校验 |
|---|---|---|---|
| host 自定义域名 | 域名→节点IP | 网关 https 端口 | 网关端口一致 |
| host 前缀域名 | 前缀.节点Domain | 网关端口 | 网关端口一致 |
| forward | 节点IP:Port | forward.Port | 端口池内且空闲 |
| proxy | 节点IP:Port | proxy.Port | 端口池内且空闲 |
| tunnel | 节点IP:bindPort | 节点 frps bind port | bind port 一致 |
| p2p | 节点IP:bindPort | 节点 frps bind port | bind port 一致 |

## 5. 愿景 / 北极星
- 北极星：故障转移后「入口自动恢复率」——自定义域名转移后无需人工改 DNS 即可达的比例。
- 愿景：节点宕机对上层访问近乎无感（域名场景），端口场景调用方可据 webhook 自动切换。

## 6. 边界
- 端口不变但 IP 变：调用方需据 webhook/历史更新 IP；更彻底方案为前置 LB/固定 VIP（本产品不内置 LB）。
- DNS 跟随依赖 DNS 服务商凭据（复用 ACME SystemCert 或全局 DNS 配置）与低 TTL。
- 不改变现有五类隧道与 failover/health 行为；新增字段只增不删。
