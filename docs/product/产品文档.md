# GOSTC 内网穿透平台 · 产品文档（增强版）

> 版本：v1.0（增强规划）｜ 状态：待评审 ｜ 配套：[PRD](PRD.md)、[开发路线图](开发路线图.md)

## 1. 产品定位

GOSTC 是一个基于 FRP 的**内网穿透与隧道管理平台**，由四部分组成：

| 组件 | 目录 | 职责 |
|---|---|---|
| 服务端（面板） | `server/` | 用户/节点/隧道管理、配置下发、计费、可观测性。Go + gin + gorm |
| 客户端 | `client/` | 运行在内网机器，注册代理、接收面板下发配置。Go |
| 网关代理 | `proxy/` | 域名解析的 HTTP/HTTPS 入口，按 Host 路由到节点 frps。Go |
| 控制台前端 | `web/` | Vue3 + naive-ui 管理界面 |

核心价值：**让内网服务安全、可控地暴露到公网**，并提供节点接入、套餐计费、流量统计等运营能力。

## 2. 现状功能盘点

平台已具备完整的隧道矩阵与运营基础：

- **六类隧道**：域名解析（host）、端口转发（forward，TCP/UDP）、私有隧道（tunnel，STCP/SUDP）、P2P 隧道（xtcp+stcp）、代理隧道（proxy，SOCKS5/HTTP）、配置隧道（frp 原生配置）。
- **节点体系**：用户可接入自有公网服务器为节点；节点功能开关、端口组、域名/泛域名、套餐（速率/并发/连接/流量包/计费周期）。
- **运营能力**：用户/用户组、积分与 CDK、签到、流量包与续费、每日流量统计、客户端在线日志、邮件服务、公告。
- **准入控制**：IP 白名单。

## 3. 现状痛点（来自真实运维与源码审计）

1. **「在线 ≠ 可用」**：客户端 ARPC 在线只代表控制通道连通，隧道可能未注册到 frps、或后端服务已宕机，面板仍显示绿色。真实案例：节点替换地址拼写错误导致 frp 隧道连不上，面板无感知，用户访问报 frp 404 才被发现。
2. **安全基线薄弱**：密码用 MD5+salt 弱哈希；节点密钥/访问密钥/DNS 凭据明文存储；无审计日志、无账号级登录锁定。（注：TOTP 两步验证与 IP 安全+验证码已存在，本期补审计/锁定/加密。）
3. **无法水平扩展**：缓存为本地文件实现，Redis 后端全是 `panic("implement me")` 桩代码，多实例部署会状态不一致。
4. **证书自动化受限**：网关 `auto-set-cert` 仅在 80 端口生效，非标端口/泛域名需手工 acme.sh，无面板化签发与续期。
5. **frp 能力未充分暴露**：引擎已支持负载均衡、健康检查、HTTP 路由、tcpmux、范围端口等，但表单未开放。
6. **网关存在死配置与已知 bug**：`sni/origin/disable-https/default` 字段未被读取；通配符域名匹配在非标准端口下失效（已在本地修复，待合入上游）。
7. **可观测性单一**：仅每日累计流量，无实时连接数/速率/延迟，无告警。
8. **无高可用**：节点单点，离线即隧道中断；无故障转移与读写分离。
9. **商业化与生态缺失**：无在线支付、无 OpenAPI/SDK、无批量操作/模板、无客户端自动更新、无国际化。

## 4. 目标用户

| 角色 | 诉求 |
|---|---|
| 个人开发者 /  homelab 玩家 | 把内网 Web/NAS/远程桌面安全暴露公网，省心、免费或低成本 |
| 小团队 / 工作室 | 多人多隧道、私密访问、稳定可用、可管理 |
| 节点提供者 / 站长 | 接入自有服务器运营节点，计费、限速、可观测、可商业化 |
| 平台管理员 | 安全合规、规模化部署、故障可感知、运营数据 |

## 5. 增强愿景（12 项）

按价值与依赖分为三档：

### 🔴 高优先级（解决「能不能放心用」）
1. **隧道健康监控 + 告警**：三态健康（客户端在线 / 隧道注册 / 后端可达）+ 主动探测 + 多渠道告警。
2. **安全加固**：bcrypt 密码、凭据加密、2FA、审计日志、登录锁定、准入黑名单。
3. **Redis 缓存后端**：实现 Redis 实现，支撑水平扩展。
4. **证书 DNS-01 自动化**：面板化 ACME 签发/续期，突破 80 端口限制。

### 🟡 中优先级（解决「好不好用、稳不稳」）
5. **frp 高级能力表单化**：负载均衡 / 健康检查 / HTTP 路由 / tcpmux / 范围端口 / 带宽限制。
6. **网关增强**：死配置清理、通配符 bug 合入上游、IP 路由、HTTP/3。
7. **实时可观测性**：连接数 / 速率 / 延迟 + 增强仪表盘。
8. **节点高可用**：故障转移、多节点注册、调度、读写分离。

### 🟢 低优先级（解决「能不能规模化运营」）
9. **支付与商业化**：在线支付、订单账单、可插拔支付网关。
10. **OpenAPI + SDK + 批量/模板**：接口文档、SDK、批量操作、隧道模板。
11. **通知 / 自动更新 / 国际化**：Webhook、客户端自动更新、i18n。
12. **P2P 增强**：NAT 类型预检、中继计费。

## 6. 北极星指标与度量

| 指标 | 现状 | 目标 |
|---|---|---|
| 隧道可用率（后端可达占比） | 不可测 | 可测且 ≥ 99% |
| 故障平均发现时间 MTTR | 用户报障（小时级） | 告警 ≤ 1 分钟 |
| 安全事故数（弱哈希/明文/无审计） | 多项基线缺失 | 基线全部达标 |
| 水平扩展能力 | 单实例 | 多实例无状态 |
| 证书自动化覆盖率 | 手工 | 面板一键签发续期 |
| 付费转化 / 营收 | 无在线支付 | 可在线充值计费 |

## 7. 范围与原则

- **全做**：12 项全部纳入，按 [开发路线图](开发路线图.md) 分 6 阶段增量交付。
- **向后兼容**：数据库只增列不删改；旧客户端/旧密码哈希平滑兼容；每阶段带 feature flag 可回滚。
- **文档先行**：本文件 + PRD + 路线图先评审，再实现。
- **不破坏现有隧道**：任何阶段不得中断已运行的六类隧道。
